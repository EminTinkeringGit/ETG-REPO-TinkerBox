
# Slitherix Inspection Robot
## 1. Executive Summary

This project delivers a compact, reliable forward-only speed control solution for a 12V DC motor using an Arduino (Uno/Nano) and an H-bridge driver. It decodes a hobby RC receiver PWM input (approximately 1000–2000 µs frame pulses), isolates the forward stick travel (1500–2000 µs), and maps that range to an 8-bit microcontroller PWM output (0–255) to provide a linear, user-controlled motor speed.

Key results and properties:

- **Direct RC integration:** Reads standard RC pulse widths and converts them to MCU PWM without extra hardware.
- **Forward-only safety:** Neutral/negative inputs and timeouts are forced to zero speed to prevent unintended motion.
- **Deterministic mapping:** The input-to-output transfer uses constrained mapping for predictable, repeatable response.
- **Platform compatibility:** Works on both Arduino Uno and Nano (ATmega328P) with the same firmware.

Recommended next steps: add lightweight filtering to suppress jitter around the neutral deadband, include a hardware current-sense or fuse for overcurrent protection, and optionally extend the firmware to support bidirectional control if reverse motion becomes required.

## 2. System Architecture & Components

The system architecture consists of four primary blocks: the control input (RC Transmitter & Receiver), the processing logic (Arduino), the power amplification stage (H-Bridge), and the actuator (12V DC Motor).

* **Microcontroller:** Arduino Uno or Arduino Nano (ATmega328P). Responsible for pulse timing measurement, signal mapping, and PWM generation.
* **Motor Driver:** H-Bridge Module (utilizing independent IN1/IN2 control logic without dedicated hardware enable pins).
* **Actuator:** 12V Small DC Motor.
* **Power Supply:** External 12V DC power supply capable of meeting the motor's stall current demands.

## 3. Circuit Schematic & Interconnections

### 3.1 Common Grounding Logic

A critical design requirement of this circuit is the common ground reference. The negative terminal of the 12V external power supply, the H-bridge logic ground, and the Arduino ground terminal are all tied together to establish a 0V reference plane for control signaling.

### 3.2 Wiring Topology

The connections are structured as follows:

| Source Component | Source Pin | Destination Component | Destination Pin | Function |
| --- | --- | --- | --- | --- |
| **RC Receiver** | Signal (S) | Arduino | D3 | Input RC Pulse Stream |
| **RC Receiver** | VCC (+) | Arduino | 5V | 5V Logic Power |
| **RC Receiver** | GND (-) | Arduino | GND | Logic Ground |
| **Arduino** | D9 (~PWM) | H-Bridge | IN1 | Forward Speed Control |
| **Arduino** | D10 (~PWM) | H-Bridge | IN2 | Locked Low (0V) for Direction |
| **12V Supply** | Positive (+) | H-Bridge | 12V / VCC | Motor Drive Power |
| **12V Supply** | Negative (-) | Arduino / H-Bridge | GND | Main System Ground |
| **H-Bridge** | OUT1 / OUT2 | DC Motor | Terminals | Motor Drive Output |

## 4. Firmware Implementation & Control Logic

### 4.1 Signal Decoding Strategy

Hobby RC receivers communicate via pulse-width modulation featuring a 20ms frame period, where the pulse width varies strictly between $1000\,\mu\text{s}$ (minimum/reverse) and $2000\,\mu\text{s}$ (maximum/forward), with $1500\,\mu\text{s}$ acting as the neutral dead-band.

The firmware utilizes the hardware-timed `pulseIn()` function on Digital Pin 3 to measure the incoming pulse duration in microseconds.

### 4.2 Mathematical Mapping & Constraints

Because the project scope mandates **forward-only operation**, the software isolates the upper half of the stick travel ($1500\,\mu\text{s}$ to $2000\,\mu\text{s}$). Values falling below $1500\,\mu\text{s}$ or experiencing signal timeouts ($>2200\,\mu\text{s}$) are filtered out and safely forced to a zero-speed state.

The valid range is mathematically mapped to an 8-bit microcontroller PWM duty cycle ($0$ to $255$) using the following transfer function:

$$f(t) = \text{constrain}\left(\text{map}(t, 1500, 2000, 0, 255), 0, 255\right)$$

Where $t$ represents the measured pulse duration in microseconds.

## 5. Testing, Calibration, and Troubleshooting

### 5.1 Telemetry Verification

During testing, debugging can be performed via the Arduino IDE Serial Monitor at 9600 baud. The print statements verify that physical movement of the transmitter joystick yields a linear progression from `0` to `255` on the calculated motor speed variable.

### 5.2 Observed Edge Cases & Mitigations

1. **Signal Inversion:** If the motor runs backward when accelerating the transmitter stick, the issue can be corrected by physically reversing the motor wires at the H-bridge output terminals (`OUT1`/`OUT2`) rather than adding processing overhead to the code.
2. **Signal Noise Jitter:** Minor fluctuations around the $1500\,\mu\text{s}$ mark can cause the motor to jitter at a standstill. This is handled gracefully by the explicit threshold safety filter (`if (rcDuration < rcMin)`).
3. **Hardware Porting:** The system was verified to be 100% logic-compatible between the Arduino Uno and Arduino Nano form factors due to shared ATmega328P architecture, provided the correct bootloader target is compiled within the development environment.
